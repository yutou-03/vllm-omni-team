
# 混合 200 请求：数据汇总（2026-11-03）

结论：四组各 200/200 完整返回；当前配置未证明约 20% 的实际流式性能收益。Gstream 明显上升，但引擎生成速度基本持平，端到端 SLO token/s、音频首段和播放连续性退化。泊松组未发生暂停；突发组只验证 Stage 0 的文本暂停，没有验证 Stage 1 暂停收益。

范围：单种子、单次成对试跑，不是正式多次重复结论。配置和权重在比较前冻结，未按结果调参。

## 1. 共同配置与负载

模型 Qwen3-Omni-30B-A3B-Instruct；6 张 A100 40GB，Thinker TP4 使用 GPU 0–3，Talker GPU 4，Code2Wav GPU 5。Stage 0/1 均为 K=16 执行名额、R=64 驻留上限，保留 KV，FIFO 等待队列。

每条轨迹 200 请求：文本 120（标准/宽松各 60），音频 80（标准/宽松各 40）；到达窗口 166.667 s，平均 1.2 请求/s。相同内容、相同种子 20261103，模型种子 42。标准/宽松文本长度上限 128/512；音频伴随文本上限 64/128，不强制生成至上限。

泊松为固定窗口内恰好 200 次到达的条件泊松过程，1 s 峰值 4 条。BurstGPT 只复用真实到达形状、统一缩放，1 s 峰值 22 条；混合内容与 SLO 由实验合成。

原生对照：相同 K16/R64 容量配置及日志的 native FIFO，关闭新增缓冲、文本限速与主动暂停。不是默认 K64、完全未经适配的原生进程。我们方案：文本输出缓冲 + Q01/Q12 接收缓冲 + 动态暂停。两个实验臂同时改变缓冲与暂停，不能单独归因暂停收益。

token 只计 Thinker 输出模型 token ID，包含音频请求伴随文本，不能把 codec frame 或 PCM sample 混加。四组均生成 41,539 个文本 token。端到端吞吐分母从首次计划到达到最后客户端完成，包含限速交付和排空；SLO token/s 的分子只计完整且通过全部预设路径 SLO 的请求 token。

Gstream 使用固定到达窗口，soft_ttft_v2，β=μ=3.3，保留连续首输出超时扣分与库存权重。TTFT 从计划到达到首个可见文本；音频首段可播放时间 TTFP 另列。两个分母含义不同，不能用 Gstream 的涨幅代表模型生成能力。

## 9. SLO、局限和可复现证据

文本标准/宽松 TTFT 1.3/5.2 s；音频 TTFP 3/6 s，伴随文本 TTFT 2.6/5.2 s。文本交付期限 45/160 s、音频 90/180 s；文本最大单次/累计断流 0.1/0.5 s，音频 0.25/0.5 s。文本可见平均 TPOT ≤1/4.8 s。

独立低负载仅 8 条校准样本，不能当作稳健的尾延迟标定。当前是一次小规模成对试跑；未测最大可持续吞吐、多个随机种子、缓冲位置消融、K8/K64 或 >512 token 预测准确性。

下一步可验证方向：保持本轮负载与权重不变，分别关闭末端限速、关闭主动暂停、拆开 Q01/Q12 放行，定位音频额外等待和断流；若安全库存不足，先修正库存形成与恢复调度，不直接降低安全门槛。未启动新轮次。
