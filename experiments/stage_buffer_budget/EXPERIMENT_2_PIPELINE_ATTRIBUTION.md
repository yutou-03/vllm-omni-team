# 实验二：阶段间库存、暂停收益与 GPU 活动的验证方案

状态：文献核查和采集工具已准备；以下音频位置对照尚未运行。采集工具烟测和纯文本 V3 结果不能证明三阶段利用率提升。

## 研究问题与已知边界

研究假设：保留 KV 的阶段内暂停，将本阶段名额转给紧急请求；接收端已接管的中间结果让后续阶段继续产生有效输出。收益必须体现为紧急请求等待/SLO 改善、下游供给持续及受害请求 SLO 保持。不同阶段可暂停不同请求，不要求三阶段同时暂停同一请求。

现有 32 条 V3 是纯文本：16 条完整链、相对末端缓冲无暂停分数 +5.42%；不能验证 Q01/Q12 的贡献。旧 V2 K16 混合路径有 15 条完整链，但分数 -0.22%、音频断流上升。V3 FIFO 运行没有独立 GPU 连续采样；scheduler 间隔不是 GPU kernel 时间。Thinker TP4 的四张卡、Talker、Code2Wav 均须单独报告。

固定模型、GPU 配比和流量时，各阶段工作量可能不相等。缓冲能改变工作时机、减少缺输入空闲；不能让轻量阶段凭空拥有更多工作，也不能增加真正瓶颈的固有计算能力。GPU 活跃更高必须与有效输出、SLO 和耗时同时解释。

### 评分口径需要明确修正来源描述

TokenFlow §3.2 的 B 是 token **生成时**的未消费库存，§7.1.3 折损阈值按输出长度比例定义。当前冻结实现按**客户端收到时**的阅读库存计算，阈值为 10 s 满分、随后 20 s 线性衰减。这是修改后的指标，不能称为原指标直接复现。把内容留在服务器尚未发送区会让当前 B 变小，而生成工作没有变化。

保留既有冻结分数。新位置消融并列报告：原分数拆分、真实消费时间线、无 w(B) 敏感性、生成至最终消费的总积压。语义 token、codec frame、PCM 不能直接相加；保留各自单位和内容对应关系，避免同一前缀不同表示重复计数。文本用同一可见 tokenizer，音频以实际可播放秒数评价。3.3 token/s 只是音频效用换算，不能用作 Talker/Code2Wav 消费速率。

## 三条可验证假设

H1：上游真实暂停期间，下游仍有完整输入并持续生成正确输出；紧急请求实际占用释放的本阶段名额。申请、入批、释放、重执行、首新 chunk 全链核对。

H2：相同工作量和资源下，阶段库存减少了**有待完成工作时因缺输入导致的空闲**。一个请求等输入而 GPU 正处理别人，不算阶段 GPU 缺料空闲。

H3：H1/H2 转化为较低 TTFT/TTFP、较少播放断流或更高 SLO 下可持续到达率。GPU 活动升高但完成更慢或 SLO 更差，不判为成功。

## 缓冲位置消融

Q01 为 Talker 接收端库存，Q12 为 Code2Wav 接收端库存，Qout 为已完成文本/音频末端库存。各组共有相同的最小传输/播放抖动容忍量、首段立即交付规则、文本 4.8 token/s 与音频 1×消费；下表指**额外可调库存**。

| 位置 | 额外库存 | 无主动暂停 | 成本感知主动暂停 |
|---|---|---|---|
| O | Qout | O0 | O1 |
| I | Q01 + Q12 | I0 | I1 |
| M | Q01 + Q12 + Qout | M0 | M1 |

原生未修改策略另留参考。先做 O0/O1/I0/I1 机制筛查，通过后做 M0/M1 和 Q01-only、Q12-only；后两组针对对应阶段拥塞，减少无意义组合。

O1 也允许根据已确认的末端可播放库存暂停 Stage0 或 Stage1，不能禁止它暂停上游以做弱对照。各组共用紧急判断、FIFO、多暂停限制、恢复优先、KV 驻留及 checkpoint/恢复估计方法，只改变额外库存位置及真实可用性。

各组保持模型、GPU/阶段映射、K_s/R_s、KV bytes、输出质量、种子、到达、逐请求 SLO 相同。固定**全路径额外 CPU 库存总字节预算**；M 组拆分预算，不能每多一个队列就多一份内存。共享张量按唯一所有权记账。上游待发送、共享内存未接收和 CPU/GPU 在途区也记录，防止队列外隐藏无限库存；它们计资源占用，不能计安全暂停库存。

另做“相同可播放覆盖时间”的敏感性；等字节与等覆盖时间是两种比较，不能声称同时满足。Q01 尚需两阶段计算，以留出标定及实际事件验证转换误差，不能直接当成最终音频秒数。

容量满导致的背压与为紧急请求主动让位分别计数。无主动暂停组也可能有容量背压。统计整个蓄水过程，不能剔除蓄水导致的延迟和空闲。各组客户放行规则相同。

成对归因：
- 末端位置的暂停增益：ΔO = G(O1) − G(O0)。
- 阶段位置的暂停增益：ΔI = G(I1) − G(I0)。
- 位置与暂停交互：ΔI − ΔO；同时公布直接比较 G(I1) 与 G(O1)。
- 联合作用：比较 M1 与 O1、I1，同时给出相同总预算下实际占用。

暂停次数是策略结果，不能筛选“恰好都暂停 16 次”的样本。另可固定一段暂停动作做受控机制回放，检验同一上游暂停时下游供料；该回放不能替代在线性能对照。

## 动态控制建议（尚未实现）

1. 每条接收库存记录保守可供给时间、原始单位、观察年龄和消费率上界。窗口覆盖 checkpoint 等待、紧急批次占用、恢复排队及首个新输出；100 ms 只作申请值。
2. 从客户端播放/首段期限向上游回推最晚产出时间，考虑下游排队和计算。仅用于受害者安全判断与恢复，不混入实验一等待队列余量排序。
3. 下游缺料时保证供给；下游库存充分且上游紧急请求等待名额时让位。多暂停联合估计新批次时间和恢复容量，不能将每条独立可暂停时间简单相加。
4. 分别记录“接收队列空”“有库存但放行时钟拦住”“传输等待”“有可运行任务但无 kernel”。现有 receiver_buffer 的空队列、蓄水 gate 和 pacing 都可能返回 None，尚缺精确分原因时长；需补状态转移和短 GPU trace。
5. 在计算余量允许时蓄水，接近上界停止补充、下界前恢复，用迟滞减少反复暂停。若库存只能靠长期压低瓶颈服务率维持，应报告不可行。改变下游 batching 另列消融，不与第一轮位置对照混合。

## GPU 指标与证据

[nvidia-smi 定义](https://docs.nvidia.com/deploy/nvidia-smi/index.html#utilization)：GPU utilization 是驱动窗口内有 kernel 执行的时间比例，不是 SM 占用率、有效 FLOPs 或显存使用率。200 ms 轮询不等于驱动窗口缩至 200 ms；collective 等待 kernel 也可能表现为 GPU 活动。

两层证据：
- 全程独立采样每卡 UUID、GPU busy、memory busy、功耗、显存和主机 monotonic。预先核对物理映射、排除共享设备的其他工作。Thinker 报四 rank 值、均值、最小值，不用六卡总均值掩盖单阶段。
- 短机制窗口用 CUDA profiler/CUPTI/Nsight 核对实际 kernel 区间，区分计算、拷贝、collective/等待和 CPU 发射间隙，与库存/暂停/入批/恢复对齐。profiling 与正式轻量采集运行分别标记。

固定共同窗口 W，逐卡 U_g = kernel_busy_time_g / W。轮询只能估计时间加权活动，精确 kernel 并集需 trace。≤10% 低活动与 ≥80% 高活动比例只作事前冻结的诊断；缺测不补零，覆盖不足 95% 不输出有效阶段均值。

缺输入空闲要求：阶段有待完成工作、没有可运行输入、无有效计算。须用状态转换与 kernel trace 相交；周期快照只能说明观察到了输入等待。全到达窗口、事前冻结的稳态窗口、排空阶段分开报告，不能只挑忙碌时段。

“三阶段都高利用率”是待检验现象。Code2Wav 工作量轻时，不应强求它一直高于 80%；需检验有待处理音频时的供给连续性，并通过提高共同到达率观察能否承接更多请求。硬件配比优化是独立实验。

## 负载与三张主图

短机制负载：
- Stage0 受限：宽松音频占据 Thinker，紧急文本/音频等待 Thinker；Q01 应维持后续阶段工作。
- Stage1 受限：宽松音频占据 Talker，紧急音频已有 Thinker 输入；Q12 应维持 Code2Wav 工作。
- 两阶段瓶颈交替：输入/音频长度和路径比例改变，各组仍使用同一轨迹。
- 不拥塞、生产消费几乎相等的对照：预期暂停机会减少，不能降低安全阈值制造触发。

校准与正式种子分离，运行顺序交错，正式条件至少 3 个种子；区间按种子/请求聚类，不把硬件样本当独立重复。音频放行变化可能改变模型输出，须核对语义文本、codec 顺序、解码完整性和音频内容可比性；不等价时先固定输入边界，停止解释为纯调度收益。

三张主图：
1. 同轴画三阶段真实执行（紧急/受害）、Q01/Q12、末端可播放库存，标出申请、入批、恢复、新 chunk，展示“上游换人、下游继续”。
2. 每阶段 GPU 全程曲线和分原因空闲，配短 kernel trace；逐卡覆盖率、TP 差异和人为放行等待明确标出。
3. 横轴共同到达率，纵轴冻结流式分数、TTFT/TTFP 达标、断流；另比较无持续积压增长且满足同一 SLO 的最大到达率。arrival-window 归一化分数不等同最大稳定吞吐。
